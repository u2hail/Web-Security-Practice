## 补全顺序（按投入产出排序，不按时间）

判断依据三条：**① 实战胜率高不高 ② 面试常不常问 ③ 能不能复用已有思路**

| 顺序 | 漏洞族 | 为什么排这个位置 | 预计投入 |
|---|---|---|---|
| **1** | **XSS** | 已有三种类型的实操基础，**只差框架**——性价比最高。而且它是「代码/数据不分离」母题的第二个实例，学完能强化总纲 | 2~3 个晚上 |
| **2** | **SSRF** | 面试高频，技巧性强（黑名单绕过变体多），且与 SQLi 的"绕过"思路同构 | 1~2 个晚上 |
| **3** | **文件上传** | 危害直接（RCE），有 upload-labs 现成靶场，逐层绕过很像 SQLi 的过滤绕过 | 2 个晚上 |
| **4** | **越权** | 实战中出现频率极高、门槛极低，**没有 payload 反而难写**——考验的是"怎么想到测" | 1 个晚上 |
| **5** | **文件包含 / 目录遍历** | 两者合并补，伪协议 + 日志投毒是经典组合链 | 1~2 个晚上 |
| **6** | **命令注入 / RCE** | 与 SQLi 同构，很快能通 | 1 个晚上 |
| **7** | **CSRF** | 概念简单，重点是 SameSite 与 token 校验细节 | 半个晚上 |
| **8** | **XXE / SSTI** | 需要一点语言/解析器基础，放在有整机靶场后一起补 | 各 1 个晚上 |
| **9** | **逻辑漏洞** | 没有标准打法，靠案例积累，放在 SRC 阶段边打边补 | 长期 |
| **10** | **反序列化** | 偏语言特性专题（Java/PHP），等基础扎实后单独开 | 后期 |
