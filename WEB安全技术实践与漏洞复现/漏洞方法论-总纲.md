# 漏洞方法论 · 总纲

> 这份文档回答一个问题：**面对一个漏洞，我该从哪几个方向去想，才算想全了。**
>
> 它不是漏洞列表，是**框架**。具体漏洞的填空内容分布在 `漏洞方法论-填空骨架/` 下，
> 每类漏洞一份，结构完全同构。

---

## 一、四问：每一问要问到什么程度

我的报告把每类漏洞按同一套"四问"整理。但光写"成因、利用链、绕过、修复"四个词没用，
**关键是每一问下面要答到什么颗粒度**。下面是标准。

### 问 1：成因 —— 为什么这个洞能存在？

要求：**说到机制，不说定义。**

| 不合格 | 合格 |
|---|---|
| "SQL 注入是因为没过滤用户输入" | "应用把用户输入拼进 SQL 字符串，导致**数据库无法区分哪部分是代码、哪部分是数据**。参数化查询之所以能修，是因为它先固定语句结构、再把参数作为纯数据传入，让用户输入永远进不到语法层" |
| "XSS 是因为没转义" | "浏览器无法区分页面里的 `<script>` 是**开发者写的**还是**用户数据里带的**。转义的本质是让用户数据以**文本**而非**标记**的身份进入 HTML 解析器" |

**共同点**：所有东西都能套进同一个母题——**系统无法区分"代码"与"数据"，
于是把数据当代码执行了。**

- SQL 注入：数据库分不清 SQL 语句和数据 → 数据被当 SQL 执行
- XSS：浏览器分不清页面标记和用户数据 → 数据被当 HTML/JS 执行
- 命令注入：Shell 分不清命令和参数 → 参数被当命令执行
- 文件包含：PHP 分不清"要读的路径"和"要执行的文件" → 数据被当代码加载
- 模板注入（SSTI）：模板引擎分不清模板和用户数据 → 数据被当模板编译

**每一类漏洞的"成因"这一问，都要能落到这个母题上，并说出它具体是在哪一层失守的。**

### 问 2：利用链 —— 从"看到这个功能"到"拿到结果"

要求：**写成一条可复现的决策链，不是一堆 payload。**

固定格式：

```
① 我看到什么？（功能点 / 参数 / 响应特征）
      ↓ 由此我假设什么？
② 假设：这里可能是什么洞，为什么这么想
      ↓ 用什么最小代价验证？
③ 验证：一条 payload / 一次请求，观察什么现象
      ↓ 现象确认了什么？
④ 确认：洞成立，边界在哪（能读什么 / 能做什么 / 能不能写）
      ↓ 怎么扩展到最终危害？
⑤ 利用：拿到实际结果
```

**核心差异点**：入门写的是"我用了什么 payload"，合格写的是
"**我当时看到 X，所以我猜 Y，我用 Z 去证，结果是 W**"。

后者才是面试官要听的。

### 问 3：绕过 —— 当开发者开始防的时候

要求：**说清"防的手段"和"为什么防不住"的对应关系。**

这是四问里的第一道分水岭。因为它考的是**对抗思维**，不是复述。

固定格式：

| 防御手段 | 它的本意 | 实测绕过方式 | 为什么能绕过 |
|---|---|---|---|
| 例：黑名单禁 `union select` | 挡住联合查询 | 大小写混杂 `uNION sELECT` | 正则没加 `/i`，只覆盖了三种大小写形态 |
| 例：过滤空格 | 打散关键字 | 用 `%09`(Tab) 代替 | 正则只写了 `[ +]`，没覆盖其它空白字符 |
| 例：转义单引号 | 阻止闭合 | 宽字节注入 `%df'` | 转义函数与连接字符集不匹配，`%df%5c` 被当作一个宽字符 |

**一句话原则**：**任何黑名单都是"列举已知"，而绕过是"找出没列举的"。**
所以绕过的思考方式不是背 payload，而是：

```
先读过滤规则（正则 / WAF 规则 / 代码）
    ↓
问：它覆盖了哪些形态？漏了哪些"等价但不同写法"？
    ↓
构造一个"语义相同、字符串不同"的输入
```

### 问 4：修复 —— 从"堵"到"隔离"

要求：**能说清"为什么这样修"，并且给出验证方法。**

三层递进：

| 层次 | 做法 | 为什么有效 / 为什么不够 |
|---|---|---|
| **根本修复** | 参数化查询 / 上下文敏感输出编码 / 白名单 / 权限校验 | 从机制上隔离"代码"与"数据"，用户输入永远进不到语法层 |
| **为什么不能靠转义过滤** | —— | 黑名单是列举已知，攻击面是无限的。**这是"堵"，不是"隔离"** |
| **临时缓解** | 降权、关报错回显、WAF 特征拦截 | 降低利用速度和影响面，但不改变洞存在的事实 |

**必须有"修复验证方法"**：用原 payload 复测 + 换手法复测（只拦一种不算修好）。
一份报告的真正价值在于"**读者能不能据此确认问题真的被修好了**"。

## 二、母题：所有漏洞为什么可以放在同一个框架里

这是我在 `六大漏洞-为什么是公共底座.md` 里的结论，这里再收敛一次：

```
所有漏洞的成因母题只有一个：

    系统无法区分「代码」与「数据」
              ↓
    于是「数据」被当「代码」执行 / 被当「指令」信任 / 被当「许可」放行
```

按"失守在哪一层"分类，漏洞族自然成组：

| 失守层 | 漏洞族 | 数据被误认为 |
|---|---|---|
| **数据库解析层** | SQL 注入 | SQL 语句 |
| **浏览器解析层** | XSS | HTML 标记 / JS 代码 |
| **操作系统命令层** | 命令注入、RCE | Shell 命令 |
| **文件系统/解释器层** | 文件包含、文件上传、目录遍历 | 可执行文件 / 可访问路径 |
| **服务端请求层** | SSRF | 可信任的请求目标 |
| **应用逻辑层** | 越权、CSRF、支付逻辑 | 已授权的请求 / 合法的操作者 |

**这张表就是"框架"本身。** 每一类漏洞的四问，都是在这张表上找"它在哪一层失守、
怎么失守、开发者修的时候堵在哪一层"。

## 三、漏洞族 × 四问 对照表

搭框架最实用的就是这张表：**把四问分别落到每类漏洞上，一目了然知道该想什么、该测什么。**

| 漏洞族 | 成因（哪一层失守） | 利用链入口（看到什么→想什么） | 绕过（对抗什么防御） | 修复（在哪层隔离） |
|---|---|---|---|---|
| **SQL 注入** | 数据库解析层：输入拼进 SQL | 参数参与查询、有回显/报错/长度差异/耗时差异 | 关键字黑名单、空格过滤、注释符过滤、转义（宽字节） | 参数化查询 + 数据库降权 |
| **XSS** | 浏览器解析层：数据进了 HTML/JS 上下文 | 参数回显到页面、且有 DOM sink 或服务端拼接 | 标签/事件黑名单、长度限制、编码过滤、CSP | **按输出上下文编码**（HTML 实体 / JS 转义 / URL 编码）+ CSP |
| **CSRF** | 应用逻辑层：请求不带"意图证明" | 关键操作无 token、Cookie 为 SameSite=None | token 校验残缺、Referer 校验可绕过 | CSRF Token + SameSite + 二次确认 |
| **SSRF** | 服务端请求层：URL 由用户控制 | 有"从 URL 抓取/预览/加载"的功能 | 内网地址黑名单（十进制 IP / 进制变体 / DNS 重绑定 / 302 跳转 / 短链接） | 白名单 + 禁跳转 + 独立网络出口 |
| **文件上传** | 文件系统/解释器层：学生后缀决定命运 | 有上传入口、文件可被访问或解析 | 前端校验（可绕过）、后缀黑名单、MIME 校验、Content-Type、魔术字节、解析漏洞（`;` / `.php.` / 二次渲染） | 白名单后缀 + 重命名 + 存储与执行分离 |
| **文件包含** | 解释器层：路径可控即代码可控 | 有 `include/require` 且路径含参数 | 后缀拼接（`%00` 截断 / 伪协议 `php://input`）、目录遍历、日志投毒 | 白名单路径映射，禁动态拼接 |
| **目录遍历** | 文件系统层：路径未归一化 | 有 `file=` / `path=` 类参数 | 编码变体（`%2e%2e%2f`、双写、`..%5c`） | 规范化路径 + 白名单 + 限定根目录 |
| **命令注入 / RCE** | 命令层：输入拼进 Shell | 有调用系统命令的功能 | 分隔符黑名单（`;`/`\|`/`&`/换行）、空格过滤、通配符、编码 | 不用 Shell（传数组参数）+ 白名单 |
| **越权** | 逻辑层：只校验"登录了"没校验"是不是你的" | 有 ID 类参数、能改他人资源 | 只在前端隐藏 / 只校验角色不校验归属 | 每次操作都校验"当前用户是否有权操作该对象" |
| **XXE** | 解析器层：外部实体被允许 | 有接收 XML 的接口 | 只过滤 `SYSTEM` 关键字、编码变体 | 禁用外部实体（`LIBXML_NOENT` 等） |
| **SSTI** | 模板引擎层：用户数据被当模板编译 | 用户输入进入了模板渲染 | 黑名单过滤 `{{` / `${` | 不把用户输入当模板，只当数据传入 |
| **反序列化** | 序列化层：不可信数据被还原成对象 | 有接收序列化数据的入口（Cookie / 参数 / 文件） | 魔术方法链构造、绕过类型校验 | 不反序列化不可信数据 + 白名单类 |

> **这张表就是我的"漏洞地图"。** 之后每学一类，就回到这里把"实测结果"那一列补实。
> 它同时也是面试自检表——随便指一行，我能不能把四问讲出来。

## 四、"通道"思想：为什么不同漏洞可以用同一套决策方式

这套思路在 SQLi 里成形，但它**不限于 SQLi**。

以 SQLi 的四种手法为例：

```
有回显位        → 联合查询      1 个请求拿一行数据
无回显但报错     → 报错注入      约 30 字符/请求
报错也不回显     → 布尔盲注      约 7 个请求/字符
连差异都没有     → 时间盲注      每问一次都要等 sleep，最慢
```

**同一个洞（库名 `security`），四种手法的成本差了 200 倍。**

抽象的结论是：

> **拿到一个洞之后，第一个问题不是"用什么 payload"，
> 而是"这个洞给我什么信号、这个信号的带宽有多宽"。**

这个思路可以直接迁移到其它漏洞：

| 漏洞族 | "信号带宽"体现在哪 |
|---|---|
| XSS | 回显点上下文（HTML 正文 > 属性 > JS 字符串 > URL，越往后越难利用） |
| SSRF | 响应是否回显（有回显可直接读内容；无回显只能靠时间/带外） |
| 盲注类 | 布尔差异 → 时间差异 → 带外（OOB），带宽依次递减 |
| 越权 | 是否返回数据（返回数据 = 可直接读；只返回状态码 = 盲越权） |

**所以"先判断信号，再选手法"是所有漏洞通用的第一步。**

## 五、报告与笔记的产出规范

### 报告（放 `测试报告与分析/`）

```
漏洞概要      —— 这类漏洞是什么、为什么存在（落到成因母题）
漏洞检测      —— 这类漏洞的检测方法论（不是通用方法论）
打靶练习      —— 完整攻击链，每步含"看到什么 → 判断什么 → 截图"
总结
  ├─ 一、影响与危害   技术上能做什么 + 本次实测到什么 + 对业务意味着什么
  ├─ 二、修复建议     根本修复 / 为何转义不够 / 临时缓解 / 同类排查 / 修复验证方法
  └─ 三、延伸思考     卡在哪（写过程不写结论）+ 学到什么
```

**硬性要求**

- 所有结论必须有实测证据（payload、回显、截图、数据库状态）
- 修复建议必须包含**可执行的验证方法**，不能只写"用参数化查询"
- 截图统一放同级 `images/`，相对路径引用
- 不写绝对路径，不编造数据

### 笔记（放 `WEB安全技术实践与漏洞复现/`）

笔记不需要报告那么正式，但**至少要覆盖四问**。判断标准：

> 三个月后回看这份笔记，我能不能**不查资料就说出四问**？不能，就是没写够。

## 六、学习阶段（按阶段，不按时间）

```
阶段一：单点漏洞原理 + 靶场验证
        目标：每个漏洞族能独立复现一次，写出四问齐全的报告
        当前：SQLi 已成体系；XSS 有实操无框架；其余待补
              ↓
阶段二：组合利用
        目标：单个洞不够用时，能串起来（如 XSS 打后台 + CSRF 加管理员）
              ↓
阶段三：完整靶机
        目标：训练"拿到目标后下一步干什么"——信息收集 → 枚举 → 假设 → 验证 → 卡住 → 换思路
        这是我最缺的能力，sqli-labs 练不到
              ↓
阶段四：真实目标（SRC）
        目标：在真实系统上跑完整流程，产出可交付报告
```

**判断能否进入下一阶段的标准**：不是"看完了多少内容"，而是
**能不能在不查资料的情况下，把当前阶段的四问讲清楚、并独立复现一次**。

## 附：这份文档怎么用

1. **学新漏洞时**：先看第三节的对照表那一行 → 到 `漏洞方法论-填空骨架/` 找对应骨架 → 按四问填空
2. **写报告时**：对照第五节的格式和硬性要求
3. **复习/面试前**：只看第三节的表格，随机指一行自测四问
4. **发现新的绕过方式时**：回到第三节对应行补进"绕过"列——**这张表是活的**
